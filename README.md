## Быстрый старт

Понадобятся [Node.js](https://nodejs.org/) 18 или новее (вместе с ним ставится npm) и [Git](https://git-scm.com/). Проверить версии можно командами `node -v` и `git --version`.

```bash
git clone https://github.com/El1teX/task-manager.git
cd task-manager
npm install

npm run dev:react   # http://localhost:5173 — версия на React
npm run dev:vue     # http://localhost:5173 — версия на Vue
```

Чтобы собрать production-версию и посмотреть её локально:

```bash
npm run build
npm run preview
```

## Возможности

- Отметки за последние 14 дней одним нажатием (на телефоне — за 7 дней), в том числе задним числом.
- Текущая и лучшая серия, процент выполнения за 30 дней, общее число отметок.
- Тепловая карта за 16 недель для выбранной привычки.
- Название, значок и цвет для каждой привычки; редактирование и удаление.
- Прогресс за сегодня в заголовке.
- Светлая, тёмная и системная тема.
- Данные хранятся в `localStorage`, синхронизируются между вкладками.
- Резервная копия: скачать в JSON и загрузить обратно (с проверкой файла).
- Дата сама обновляется в полночь, если вкладка открыта.
- Адаптивная вёрстка, работа с клавиатуры, подписи для скринридеров, учёт `prefers-reduced-motion`.

## Как пользоваться

1. **Добавьте привычку.** Нажмите «Добавить привычку», введите название, выберите значок и цвет бусин. На пустом экране есть готовые примеры — их можно добавить в один клик.
2. **Отмечайте дни.** Каждая бусина в строке — один день, самая правая с обводкой — сегодня. Нажатие ставит или снимает отметку. Пропущенный день можно отметить задним числом.
3. **Следите за серией.** Под названием привычки видно, сколько дней подряд она выполняется, а соседние отмеченные дни соединяются цветной нитью.
4. **Смотрите статистику.** Нажмите на название привычки — справа (на телефоне ниже) появятся серии, процент за 30 дней и тепловая карта за 16 недель.
5. **Редактируйте.** Кнопка с карандашом открывает настройки привычки: там можно переименовать её, сменить цвет или удалить.
6. **Сохраняйте копию.** Внизу страницы есть «Скачать копию» и «Загрузить из файла». Так можно перенести привычки в другой браузер или на другое устройство.
7. **Меняйте тему.** Кнопка в правом верхнем углу переключает тему: как в системе → светлая → тёмная.

Всё работает с клавиатуры: `Tab` переходит между бусинами и кнопками, `Enter` или пробел ставит отметку, `Esc` закрывает окно.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev:react` | Запускает React-версию в режиме разработки |
| `npm run dev:vue` | Запускает Vue-версию в режиме разработки |
| `npm test` | Прогоняет тесты общей логики |
| `npm run build` | Собирает обе версии и стартовую страницу в `dist/` |

После `npm run build` получается такая структура:

```
dist/
├── index.html   ← страница выбора версии
├── react/       ← сборка React
└── vue/         ← сборка Vue
```

## Архитектура

Вся предметная логика лежит в `packages/core` и не знает о фреймворках. Функции чистые: принимают данные и возвращают новые, ничего не меняя на месте. Поэтому ядро легко тестировать, а обе версии интерфейса остаются тонкими.

```
            ┌──────────────────────┐
            │     @beads/core      │
            │ даты · привычки ·    │
            │ хранилище · стили    │
            └──────────┬───────────┘
          ┌────────────┴────────────┐
   ┌──────▼──────┐           ┌──────▼──────┐
   │  apps/react │           │  apps/vue   │
   │ хуки + JSX  │           │ composables │
   └─────────────┘           └─────────────┘
```

Как одна и та же задача решается в двух фреймворках:

| Задача | React | Vue |
| --- | --- | --- |
| Состояние и сохранение | `useState` + `useEffect` | `ref` + `watch({ deep: true })` |
| Обновление привычки | Новый массив через `map` | Замена элемента в реактивном массиве |
| Производные данные | `useMemo` / вычисление при рендере | `computed` |
| Текущий день | Хук `useToday` | Composable `useToday` |
| События компонентов | Колбэки в пропсах (`onToggle`) | `emit('toggle')` |
| Модальное окно | `<dialog>` + `useRef` | `<dialog>` + `ref` в шаблоне |

## Формат данных

Данные лежат в `localStorage` под ключом `beads:v1`. Файл резервной копии имеет тот же формат:

```json
{
  "version": 1,
  "theme": "system",
  "habits": [
    {
      "id": "3f1c…",
      "name": "Пить воду",
      "emoji": "💧",
      "color": "cobalt",
      "createdAt": "2026-09-01",
      "done": { "2026-09-24": true, "2026-09-25": true }
    }
  ]
}
```

Дни хранятся как строки `YYYY-MM-DD` по местному времени — так отметка не переезжает на соседний день из-за часового пояса. При загрузке данные проверяются: неизвестные цвета заменяются на цвет по умолчанию, некорректные даты и пустые привычки отбрасываются, повторяющиеся `id` получают новые значения.

Обе версии используют один ключ, поэтому в одном браузере на одном домене видят одни и те же привычки.

### Как считаются серии

- **Текущая серия** — сколько дней подряд привычка выполнена, считая назад от сегодня. Если сегодня ещё не отмечено, счёт идёт от вчера: день не закончился, и серия не обнуляется с утра.
- **Лучшая серия** — самая длинная цепочка подряд идущих отметок за всё время.
- **За 30 дней** — доля отмеченных дней за последние 30, но не раньше начала отслеживания привычки.

## Публикация на GitHub Pages

1. Убедитесь, что код лежит в ветке `main`.
2. В репозитории откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` на каждый пуш в `main` установит зависимости, прогонит тесты, соберёт проект и опубликует `dist/`.
4. Сайт появится по адресу https://el1tex.github.io/task-manager/. Сборка использует относительные пути, поэтому репозиторий можно переименовать или форкнуть без правок в коде.

## Тесты

```bash
npm test
```

Тесты покрывают ядро: проверку дат, склонения, переключение отметок, текущую и лучшую серию (в том числе через границу месяца), процент выполнения, тепловую карту, нормализацию импортируемых данных и сохранение в хранилище.

## Как внести изменения

1. Сделайте форк репозитория или создайте ветку: `git checkout -b feature/название`.
2. Если меняете логику — правьте `packages/core` и добавьте тест в `packages/core/test`.
3. Если меняете интерфейс — внесите изменение в обе версии (`apps/react` и `apps/vue`), чтобы они оставались одинаковыми.
4. Проверьте, что всё работает: `npm test` и `npm run build`.
5. Сделайте коммит в стиле [Conventional Commits](https://www.conventionalcommits.org/ru/) (`feat:`, `fix:`, `docs:`) и откройте Pull Request.

## Идеи для развития

- Цели не на каждый день, а N раз в неделю.
- Перетаскивание привычек для смены порядка.
- Архив вместо удаления.
- Напоминания через Notification API и PWA для работы офлайн.
- Синхронизация между устройствами через бэкенд.
- Компонентные тесты для обеих версий (Testing Library).
